### 1. BASE SOLVER CLASS (`solvers/base_solver.py`)

Create an abstract base class that ALL spatial optimization problems must inherit from. This ensures consistency and extensibility.

**Required Methods:**
```python
from abc import ABC, abstractmethod
from typing import Dict, List, Any, Optional
import geopandas as gpd

class SpatialOptimizationProblem(ABC):
    """
    Abstract base class for all spatial optimization problems.
    
    Academic Research Requirements:
    - Full provenance tracking (citations, methodology)
    - Reproducible solutions (all parameters stored)
    - Clear mathematical formulation documentation
    """
    
    @abstractmethod
    def get_metadata(self) -> Dict[str, Any]:
        """
        Returns comprehensive problem metadata for academic documentation.
        
        Must include:
        - name: Full problem name
        - short_name: Identifier (e.g., "p-median")
        - category: Problem category (coverage, distance, equity, etc.)
        - description: Clear problem description
        - mathematical_formulation: LaTeX or plain text formulation
        - academic_refs: List of key academic papers (APA format)
        - complexity: Computational complexity (e.g., "NP-hard")
        - typical_use_cases: List of real-world applications
        - keywords: Search/detection keywords
        - variants: Known problem variants
        """
        pass
    
    @abstractmethod
    def get_conversation_prompts(self) -> Dict[str, Any]:
        """
        Defines conversation flow for this problem type.
        
        Must include:
        - problem_detection: Keywords/phrases to detect this problem
        - parameter_questions: List of questions to elicit parameters
          Each question should have: param name, question text, type, 
          validation rules, help text
        - constraint_suggestions: Proactive constraint suggestions
        - explanation_template: Template for explaining solutions
        """
        pass
    
    @abstractmethod
    def get_required_data(self) -> Dict[str, Dict[str, Any]]:
        """
        Specifies required geospatial data inputs.
        
        For each data type (demand_points, candidate_sites, etc.):
        - required: bool
        - description: What this data represents
        - required_fields: List of required GeoDataFrame columns
        - optional_fields: List of optional columns
        - geometry_type: Point, Polygon, LineString
        """
        pass
    
    @abstractmethod
    def validate_parameters(self, params: Dict[str, Any]) -> tuple[bool, Optional[str]]:
        """
        Validates problem-specific parameters.
        Returns: (is_valid, error_message)
        """
        pass
    
    @abstractmethod
    def solve(
        self,
        data: Dict[str, gpd.GeoDataFrame],
        parameters: Dict[str, Any],
        constraints: Dict[str, Any],
        distance_metric: str = "euclidean"
    ) -> Dict[str, Any]:
        """
        Solves the optimization problem.
        
        Returns standardized solution format:
        {
            "status": "optimal" | "feasible" | "infeasible" | "error",
            "objective_value": float,
            "selected_facilities": List[int],  # Indices
            "assignments": Dict[int, int],  # demand_id -> facility_id
            "metrics": {
                "total_distance": float,
                "average_distance": float,
                "max_distance": float,
                "coverage_percentage": float,
                # ... problem-specific metrics
            },
            "solution_time": float,
            "solver_details": {
                "solver": "gurobi" | "pulp" | "custom",
                "gap": float,
                "iterations": int,
                "formulation": str  # Brief description
            },
            "academic_metadata": {
                "algorithm_used": str,
                "references": List[str],
                "assumptions": List[str]
            }
        }
        """
        pass
    
    @abstractmethod
    def explain_solution(
        self,
        solution: Dict[str, Any],
        data: Dict[str, gpd.GeoDataFrame],
        detail_level: str = "standard"
    ) -> str:
        """
        Generates human-readable explanation.
        
        detail_level options:
        - "brief": 2-3 sentences
        - "standard": Paragraph with key insights
        - "detailed": Full explanation with rationale
        - "academic": Technical explanation with methodology
        """
        pass
    
    def get_visualization_config(self) -> Dict[str, Any]:
        """
        Optional: Problem-specific visualization settings.
        Override for custom map styling.
        """
        return {
            "facility_marker": {"color": "red", "size": 10, "icon": "circle"},
            "demand_marker": {"color": "blue", "size": 5, "icon": "circle"},
            "show_assignments": True,
            "assignment_line_color": "gray",
            "show_service_areas": False
        }
    
    def sensitivity_analysis(
        self,
        data: Dict[str, gpd.GeoDataFrame],
        parameters: Dict[str, Any],
        constraints: Dict[str, Any],
        vary_param: str,
        values: List[Any]
    ) -> List[Dict[str, Any]]:
        """
        Optional: Performs sensitivity analysis.
        Default implementation solves for each parameter value.
        """
        pass
```

**Implementation:**
```python
import anthropic
from typing import List, Dict, Any, Optional
import json

class ConversationManager:
    """
    Manages conversation with Claude API following SDK best practices.
    
    Key Responsibilities:
    - Maintain complete conversation history (Claude is stateless)
    - Include problem state in every request
    - Handle streaming responses (optional)
    - Parse structured outputs (JSON when needed)
    - Error handling and retry logic
    """
    
    def __init__(self, api_key: str, problem_registry):
        self.client = anthropic.Anthropic(api_key=api_key)
        self.problem_registry = problem_registry
        self.model = "claude-sonnet-4-20250514"
        self.max_tokens = 4096
    
    def chat(
        self,
        user_message: str,
        conversation_history: List[Dict[str, str]],
        problem_state: Dict[str, Any],
        uploaded_data_summary: Optional[Dict] = None
    ) -> Dict[str, Any]:
        """
        Send message to Claude with full context.
        
        Returns:
        {
            "response": str,  # Claude's text response
            "actions": List[Dict],  # Any actions to take (e.g., trigger optimization)
            "updated_state": Dict  # Updated problem state
        }
        """
        
        # Build comprehensive context
        system_prompt = self._build_system_prompt()
        
        # Prepare messages with full history + current state
        messages = self._prepare_messages(
            user_message,
            conversation_history,
            problem_state,
            uploaded_data_summary
        )
        
        # Call Claude API
        try:
            response = self.client.messages.create(
                model=self.model,
                max_tokens=self.max_tokens,
                system=system_prompt,
                messages=messages
            )
            
            # Parse response
            return self._parse_response(response, problem_state)
            
        except anthropic.APIError as e:
            return {
                "response": f"I encountered an error: {str(e)}. Please try again.",
                "actions": [],
                "updated_state": problem_state
            }
    
    def _build_system_prompt(self) -> str:
        """
        Constructs comprehensive system prompt with all problem types.
        
        Must include:
        - Role definition (spatial optimization expert for academic research)
        - Available problem types with full metadata
        - Conversation guidelines
        - Output format instructions (when to return JSON actions)
        - Academic context and citation requirements
        """
        
        problems_info = self.problem_registry.list_problems()
        
        prompt = f"""You are an expert spatial optimization assistant for academic research.
You help urban planners and city administrators solve facility location problems.

# Available Problem Types

You can help solve {len(problems_info)} types of spatial optimization problems:

"""
        
        for prob in problems_info:
            prompt += f"""
## {prob['name']} ({prob['short_name']})

**Description:** {prob['description']}

**Mathematical Formulation:**
{prob.get('mathematical_formulation', 'See academic references')}

**Use Cases:** {', '.join(prob['typical_use_cases'])}

**Key References:**
{chr(10).join(f'  - {ref}' for ref in prob['academic_refs'][:2])}

**Detection Keywords:** {', '.join(prob['keywords'])}

---
"""
        
        prompt += """

# Your Responsibilities

1. **Problem Identification**: Listen carefully and identify the appropriate problem type
2. **Academic Rigor**: Provide technically accurate information with proper citations
3. **Parameter Elicitation**: Ask targeted questions based on problem requirements
4. **Data Guidance**: Help users understand what geospatial data they need
5. **Solution Explanation**: Explain both the "what" and the "why" of solutions
6. **Iterative Refinement**: Support what-if analysis and constraint modifications

# Conversation Guidelines

- Start broad: Let users describe challenges naturally
- Confirm problem type before diving into parameters
- Ask one question at a time (avoid overwhelming users)
- Provide academic context when relevant
- Be explicit about assumptions
- Always maintain full conversation context

# Output Format

**Normal conversation**: Respond with natural language text

**When ready to optimize**: Return JSON in this exact format:
{
  "action": "optimize",
  "problem_type": "p-median",
  "parameters": {...},
  "constraints": {...}
}

**When user uploads data**: Acknowledge and summarize the data

**When explaining solutions**: Use clear structure with metrics, rationale, and implications

# Academic Context

Users may request:
- Mathematical formulations
- Algorithm details
- Computational complexity analysis
- Literature references
- Comparative analysis of problem types

Always be prepared to discuss theoretical foundations while maintaining practical focus.

# Critical Rules

1. NEVER proceed to optimization without confirming problem type and parameters
2. ALWAYS validate that required data has been uploaded
3. INCLUDE full conversation context in your responses
4. CITE academic sources when discussing methodology
5. EXPLAIN trade-offs and limitations clearly
"""
        
        return prompt
    
    def _prepare_messages(
        self,
        user_message: str,
        conversation_history: List[Dict[str, str]],
        problem_state: Dict[str, Any],
        uploaded_data_summary: Optional[Dict]
    ) -> List[Dict[str, str]]:
        """
        Prepares message array with full context.
        
        CRITICAL: Include COMPLETE conversation history and current state.
        Claude has no memory between requests.
        """
        
        messages = []
        
        # Add conversation history
        for msg in conversation_history:
            messages.append({
                "role": msg["role"],
                "content": msg["content"]
            })
        
        # Build current message with embedded state
        current_content = f"""User message: {user_message}

# Current Problem State

Problem Type: {problem_state.get('problem_type', 'Not yet identified')}
Parameters Collected: {json.dumps(problem_state.get('parameters', {}), indent=2)}
Constraints Defined: {json.dumps(problem_state.get('constraints', {}), indent=2)}
"""
        
        if uploaded_data_summary:
            current_content += f"""
# Uploaded Data Summary

{json.dumps(uploaded_data_summary, indent=2)}
"""
        
        if problem_state.get('solution'):
            current_content += f"""
# Current Solution

Status: {problem_state['solution'].get('status')}
Objective Value: {problem_state['solution'].get('objective_value')}
"""
        
        messages.append({
            "role": "user",
            "content": current_content
        })
        
        return messages
    
    def _parse_response(
        self,
        response,
        problem_state: Dict[str, Any]
    ) -> Dict[str, Any]:
        """
        Parses Claude's response and extracts actions.
        
        Detects:
        - JSON action requests (optimization trigger)
        - State updates (parameter collection)
        - Normal conversational responses
        """
        
        text_response = response.content[0].text
        
        # Check for JSON action
        if "action" in text_response and "{" in text_response:
            try:
                # Extract JSON (may be wrapped in markdown)
                json_str = text_response
                if "```json" in json_str:
                    json_str = json_str.split("```json")[1].split("```")[0]
                elif "```" in json_str:
                    json_str = json_str.split("```")[1].split("```")[0]
                
                action_data = json.loads(json_str.strip())
                
                if action_data.get("action") == "optimize":
                    return {
                        "response": "I'm ready to solve your problem. Let me run the optimization...",
                        "actions": [action_data],
                        "updated_state": problem_state
                    }
            except json.JSONDecodeError:
                pass  # Not a valid action, treat as normal text
        
        # Normal conversation
        # Try to extract state updates from conversation
        updated_state = self._extract_state_updates(text_response, problem_state)
        
        return {
            "response": text_response,
            "actions": [],
            "updated_state": updated_state
        }
    
    def _extract_state_updates(
        self,
        response_text: str,
        current_state: Dict[str, Any]
    ) -> Dict[str, Any]:
        """
        Attempts to extract parameter/constraint updates from conversation.
        This is a heuristic approach - may need refinement.
        """
        # Implementation: Pattern matching, keyword detection, etc.
        # For MVP, can return current_state unchanged
        return current_state

#### `docs/problems/p_median.md`
```markdown
# P-Median Problem

## Mathematical Formulation

**Objective**: Minimize total (or average) weighted distance from demand points to facilities.

**Decision Variables**:
- $x_j \in \{0,1\}$: 1 if facility located at candidate site $j$
- $y_{ij} \in \{0,1\}$: 1 if demand point $i$ assigned to facility $j$

**Objective Function**:
$$\min \sum_{i \in I} \sum_{j \in J} d_{ij} w_i y_{ij}$$

**Constraints**:
1. Locate exactly $p$ facilities: $\sum_{j \in J} x_j = p$
2. Each demand assigned to one facility: $\sum_{j \in J} y_{ij} = 1, \forall i \in I$
3. Assignment only to open facilities: $y_{ij} \leq x_j, \forall i \in I, j \in J$

## Complexity
NP-hard (Kariv & Hakimi, 1979)

## Applications
- Warehouse location
- Distribution center placement
- Public facility siting (schools, libraries)
- Emergency service location

## Academic References

1. Hakimi, S. L. (1964). Optimum locations of switching centers and the absolute centers and medians of a graph. *Operations Research*, 12(3), 450-459.

2. ReVelle, C. S., & Swain, R. W. (1970). Central facilities location. *Geographical Analysis*, 2(1), 30-42.

3. Kariv, O., & Hakimi, S. L. (1979). An algorithmic approach to network location problems. *SIAM Journal on Applied Mathematics*, 37(3), 513-538.

## Implementation Notes

### Algorithm
- Uses Mixed Integer Programming (MIP) formulation
- Solvers: Gurobi (preferred) or PuLP (open-source)
- Typical solve time: <10 seconds for 100 demand points, 50 candidates

### Distance Metrics
- Euclidean: Default, fastest
- Manhattan: Grid-based problems
- Network: Real road distances (requires OSMnx)

## Usage Example

```python
from solvers.registry import problem_registry

# Get solver
solver = problem_registry.get_problem("p-median")

# Prepare data
data = {
    "demand_points": demand_gdf,  # GeoDataFrame with demand weights
    "candidate_sites": candidate_gdf
}

# Solve
solution = solver.solve(
    data=data,
    parameters={"n_facilities": 5, "objective": "total"},
    constraints={},
    distance_metric="euclidean"
)

print(f"Status: {solution['status']}")
print(f"Objective: {solution['objective_value']:.2f}")
print(f"Selected sites: {solution['selected_facilities']}")
```

## Variants

- **Capacitated P-Median**: Facilities have capacity limits
- **P-Median with Forbidden Pairs**: Certain demand-facility assignments prohibited
- **Weighted P-Median**: Different weights for facilities
- **Probabilistic P-Median**: Stochastic demand
```

## CRITICAL IMPLEMENTATION NOTES

### Claude API Integration
1. **Always include full conversation history** - Claude is stateless
2. **Embed problem state in every request** - See conversation_manager.py pattern
3. **Use streaming for better UX** (optional enhancement)
4. **Handle rate limits** - Implement exponential backoff
5. **Parse JSON actions carefully** - Claude may wrap in markdown

### Streamlit Best Practices
1. **Use session_state for all persistence**
2. **Minimize reruns** - use callbacks where possible
3. **Cache expensive operations** - use @st.cache_data
4. **Handle file uploads properly** - store in session_state immediately
5. **Use st.rerun() sparingly** - only when state changes require full refresh

### Optimization Solvers
1. **Always try Gurobi first**, fall back to PuLP
2. **Set time limits** to prevent hanging
3. **Validate data before solving** - check for empty datasets, invalid geometries
4. **Store solution metadata** - algorithm, parameters, assumptions for reproducibility
5. **Handle infeasibility gracefully** - explain why no solution exists

### Geospatial Data
1. **Always reproject to common CRS** before distance calculations
2. **Validate geometries** - check for invalid shapes, self-intersections
3. **Handle large datasets** - consider spatial indexing for >1000 points
4. **Use appropriate distance metrics** - Euclidean for small areas, network for cities

### Academic Requirements
1. **Every solver must have academic references**
2. **Document mathematical formulation clearly**
3. **Include complexity analysis**
4. **Provide reproducibility information** - save all parameters
5. **Enable comparison across problem types** - standardized metrics
